# LIS Automatic: project structure and working flow

## Folder structure

```text
LIS AUTOMATIC/
|-- GUI/                         User interface modules
|   |-- main_gui.py              Main Qt window, result table, and patient search
|   |-- glucose_panel.py         Glucose panel and notifications
|   |-- alerts.py                Critical alert interface and behavior
|   `-- common.py                Shared UI colors and draggable dialog
|-- config/                      Runtime settings and JSON configuration
|   |-- __init__.py              Loads settings and test mappings
|   |-- test_map.json            Maps test IDs/PIDs to readable names
|   `-- thresholds.json          Configured alert thresholds and units
|-- core/                        Application processing and alert storage
|   |-- network_watcher.py       Copies and watches LIS result logs
|   |-- parser_logic.py          Parses logs and maps result rows
|   |-- alert_rules.py           Loads and validates alert rules
|   `-- alert_store.py           Persists alerts in SQLite
|-- dependencies/
|   `-- requirements.txt         Python package requirements
|-- tests/
|   `-- test_lab.py              Creates a sample result log for manual testing
|-- threshold_editor/
|   |-- editor.py                Standalone threshold editor UI
|   `-- LIS AUTOMATIC.code-workspace
|-- docs/                        Project documentation and references
|-- main.py                      Application entry point
|-- run_lab.bat                  Launcher with a command window
|-- run_lab.bat - Shortcut.lnk   Windows shortcut to the launcher
|-- run_lab.vbs                  Launcher without a command window
`-- __pycache__/                 Automatically generated Python bytecode
```

`.git/` contains Git history. Python may create `__pycache__/` folders while
running; they are generated bytecode caches and are not application source.

## Application working flow

1. Start the app using `run_lab.bat` or `run_lab.vbs`. Both launch `main.py`.
2. `main.py` creates the Qt application and `GUI/main_gui.py` window. It starts
   the network synchronization and file watcher from `core/network_watcher.py`.
3. The sync task reads the network and local watch paths from `config/`, then
   copies today's LIS result logs into the local watch folder. The watcher waits
   for each log to finish changing before processing it.
4. `core/parser_logic.py` reads tab-separated log rows, filters hidden test IDs,
   and uses `config/test_map.json` to get test names. Parsed results are sent to
   the main window, which records their receipt time.
5. `GUI/main_gui.py` displays and filters results, with the newest received
   results at the top and times in 12-hour format. It classifies each result as
   OK, abnormal, an error, or missing. The sidebar switches the right-hand view
   between live results, glucose results, and recent critical-range history.
6. `GUI/alerts.py` handles missing results, technical errors, numeric thresholds,
   and alert acknowledgments. Rules come from `config/thresholds.json`, are
   validated by `core/alert_rules.py`, and are stored by `core/alert_store.py`
   in a local SQLite database. Glucose notification acknowledgments are also
   saved there so acknowledged results are not shown again after restart.

## Setup and configuration

- Install dependencies from the project root with
  `py -m pip install -r dependencies/requirements.txt`.
- Set the network source and local watch folder in `config/__init__.py`.
- Edit test ID/name mappings in `config/test_map.json`.
- Threshold values are in `config/thresholds.json`. The current values are
  demo alert triggers and must be reviewed and approved by the laboratory
  director before clinical use.
- `threshold_editor/editor.py` is a standalone editor and is not opened
  automatically by the main application.
- Run the manual sample-log helper from the project root with
  `py -m tests.test_lab`.
